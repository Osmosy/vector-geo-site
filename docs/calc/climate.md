# Склонение и ветер (этап 4)

## Магнитное склонение

Карта звёзд и горы считаются по истинному северу, а на месте азимут меряют компасом. Разница —
магнитное склонение, и в 2026 году она не нулевая нигде, где мы работаем: Лондон +1.24°,
Санкт-Гоар +3.55°, Нижний Новгород +13.76°, Монтевидео −11.81°.

Считается по модели WMM (коэффициенты NOAA, пакет `pygeomag`), офлайн, на десятичную дату
пакета. Поля в пакете:

| Поле | Смысл |
|---|---|
| `orientation.declination_deg` | склонение, градусы, восточное положительное |
| `orientation.facing_true_deg` | азимут фасада по истинному северу (как раньше) |
| `orientation.facing_mag_deg` | то же по компасу: `истинный − склонение` |

Восточное склонение вычитается: при +1.24° истинный азимут 180° компас показывает как 178.8°.
Обратный перевод (`компасный + склонение`) делает потребитель, если ему дали компасный азимут.

## Ветер

Источник — ERA5 через archive API Open-Meteo (ключ не нужен), суточные значения за 10 лет
(2016–2025, 3653 дня): доминирующее направление на 10 м и средняя скорость.

Из суточных значений считается вектор переноса: для направления `d` («откуда дует») и скорости
`s` — `u = −s·sin d`, `v = −s·cos d`; средний перенос даёт направление «откуда»
`atan2(−u, −v)`. Среднее по углам без векторов дало бы неверный ответ на каждый день с
противоположным ветром.

| Поле | Смысл |
|---|---|
| `exposure.wind_prevailing_deg` | преобладающее направление «откуда», градусы |
| `exposure.wind_prevailing_mountain` | та же гора (из 24) |
| `exposure.wind_speed_ms` | средняя скорость, м/с |
| `exposure.wind_calm_share` | доля штилей (сутки со средней < 3 км/ч) |
| `exposure.wind_seasonal` | то же отдельно для зимы (12–2) и лета (6–8) |
| `exposure.wind_days` | сколько суток в выборке |
| `sectors[].wind_share` | повторяемость направления по секторам (сумма ≈ 1) |

Лондон, Сити: юго-запад, 235.8° (申), 3.97 м/с; зима 234.1° / 4.38 м/с, лето 241.0° / 3.69 м/с,
штилей 0.2 %. Это совпадает с климатической нормой для Лондона, и проверка лежит в
`tests/golden/london-city/expect.yaml` → `climate` (фикстура — `fixtures/wind.json`).

## Почему не «роза ветров из головы»

Догадка о ветре хуже пустого поля: ветер в пакете нужен, чтобы отличать 凹风 (ветер в лоб)
от защищённого места, и подставить туда «наверное, с запада» — значит соврать в решении.
Если архива нет, поля остаются `null`, в `quality.warnings` пишется причина.

## Границы метода

- ветер — региональный: сетка ERA5 9–30 км, местная тяга в ущелье или между домами там не
  видна; для оценки «откуда в этом районе» этого достаточно, для «дует ли в этом дворе» — нет;
- высота 10 м, а не 2 м: у земли скорость ниже;
- дневная детализация потеряна: суточное доминирующее направление не различает ночной и
  дневной бриз;
- порывы не считаются: `wind_speed_ms` — средняя, не максимум;
- `exposure.enclosure_index` (замкнутость рельефа) остаётся отдельным полем и с ветром
  напрямую не пересчитывается — это разные измерения.
