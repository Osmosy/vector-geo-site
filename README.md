Геоданные местности для фэншуй-интерпретации: рельеф, вода, ориентация. **Модуль только
измеряет** — он не выносит суждений «благо / неблаго». Чтение форм по канонам и карта
летящих звёзд остаются навыку [vector-fengshui-bazi](https://github.com/Osmosy/vector-fengshui-bazi).

## Что делает

Вход: координаты, адрес или населённый пункт (+ по желанию азимут фасада и год постройки).
Выход: каталог участка с `site_pack.json` (схема `site_pack/1`) и схемами в `figures/`:
отмывка рельефа, роза 24 гор, профиль горизонта.

## Результат на реальных данных: Лондон, Сити

```bash
uv pip install --python .venv/bin/python -e .
```

Зависимости: `numpy`, `rasterio`, `pyproj`, `pydantic`. Сеть нужна только для скачивания

## Использование

```bash
geosite resolve "51.5138, -0.0984"            # точка, тип, точность, зона UTM
geosite frame   "Лондон, Сити"                # три охвата и UTM
geosite fetch   "Лондон, Сити"                # тайлы DEM в кеш
geosite terrain "51.5138, -0.0984"            # 24 горы, горизонт, четыре духа
geosite pack    "51.5138, -0.0984" --facing 180 --year 2018
geosite run     "Лондон, Сити" --facing 180 --year 2018
geosite schema  > schema/site_pack-2.json
```

Если фасад не задан, ось считается по модели (спина к главной возвышенности мезо-охвата) и
помечается `source: model`, `confidence: low` — карту звёзд по такой оси без подтверждения
пользователя считать нельзя.

## Что именно считается

- **24 горы** — сектора по 15° (гора 子 центрирована на севере, 352.5°…7.5°), кольца
  0–0.5 / 0.5–2 / 2–8 / 8–50 км: максимум и среднее превышение над точкой, угол горизонта,
  доля возвышенностей, азимут самого высокого луча.
- **Четыре духа** — от оси участка, а не от сторон света: черепаха (спина ±45°), птица
  (фасад ±45°), дракон (слева), тигр (справа); высота, расстояние, непрерывность охраны,
  разница дракон − тигр.
- **Драконья жила** — восхождение по градиенту от точки до локального максимума: длина,
  перепад, число изгибов (смена направления больше 45°), сёдла (провалы на пути).
- **Точка** — уклон, экспозиция, форма (гребень / низина / склон / уступ), превышение над
  окрестностью в радиусе 200 м.

## Вода

```bash
geosite water "51.5138, -0.0984"            # ближайшие водотоки с признаками
geosite pack  "51.5138, -0.0984" --facing 180 --year 2018
```

Источник — OpenStreetMap через Overpass (ODbL), ответы кешируются. Река в OSM разрезана на
десятки ways, поэтому линии сначала склеиваются по имени, и только потом измеряются — иначе
«ближайшая река» оказывается случайным куском в 200 м длиной.

Кусок `way(around:8 км)` обрывается на границе выборки, а устье притока нарисовано узлом на
осевой главной реки — этого узла в выборке нет, и слияние не находится. Поэтому к выборке
добавляются члены отношений `waterway=river|stream|canal` (`rel → way(r)`); кусок без своего
имени получает имя отношения. Склейка режется окном `max(1.5·R, 12 км)` вокруг участка, а теги
для приливности и порядка отрисовки берутся у куска, ближайшего к участку. Правило целиком —
[docs/calc/rivers.md](docs/calc/rivers.md).

Что считается по каждой воде:

| Признак | Как |
|---|---|
| Ближайшее расстояние | до ломаной русла, метры |
| Петля или изгиб | `ratio = длина по руслу / разрыв` + поворот русла ≥ 180° + площадь кольца ≥ 0.05·gap²; петля — только при `ratio ≥ 3` вместе с этими двумя условиями, иначе изгиб. Положение участка — `site_position`: `inside` / `outside_convex` (反弓) / `outside_concave` |
| Приливность | тег OSM `tidal`, иначе таблица `data/tidal_limits.json` (Темза — Теддингтон); нет данных — `null`, без догадок |
| 來水 / 去水 | азимуты входа и выхода из круга 2 км → горы |
| Обнимает или отворачивается | сторона участка относительно центра кривизны: `inner` — участок внутри изгиба, `outer` — снаружи; радиус кривизны в метрах |
| Прямой участок у участка | радиус кривизны больше 5 км |
| Слияния | пересечения разных водотоков и общие узлы OSM: расстояние, гора, тип; у реки одна запись, слияния собираются по всем её кускам |
| Доля воды | по полигонам OSM аналитически в UTM (кольца 0.5–2 и 2–8 км), мелкие пруды отброшены; длина линейной воды — рядом (правило — [docs/calc/water_share.md](docs/calc/water_share.md)) |
| Мир, эталоны | 13 мест вне Европы с фикстурами: сетка, полушарие, море, письменность — [docs/calc/world_coverage.md](docs/calc/world_coverage.md) |
| Мир, живые прогоны | что ломается вне Европы: отношения OSM, море в кольце, пустые кольца, дно океана — [docs/calc/world_smoke.md](docs/calc/world_smoke.md) |
| Мир | имена любой письменности, сезонная вода, приливы по берегу, разреженный OSM и HydroRIVERS — [docs/calc/world_water.md](docs/calc/world_water.md) |
| Геометрия | сетка (UTM или азимутальная), поправка на сходимость меридианов, линия перемены дат, полюса — [docs/calc/geometry.md](docs/calc/geometry.md) |
| Рельеф — земля | DTM из лидара или GEDTM30, цепочка и реестр — [docs/calc/dtm.md](docs/calc/dtm.md); без DTM — DSM с `no_dtm` и понижением уверенности |
| Рельеф | `files.dem` с `kind` (`dsm_smoothed` сейчас, `dtm` в PR 7), `dem_layer` у каждого поля по рельефу, уверенность по П7 — [docs/calc/dem.md](docs/calc/dem.md) |
| Калибровка | по клиньям: `water_share` (выбранное), `water_share_osm`, `water_share_wc`, уверенность и причина; допуски 1/3 п.п., правило выбора — [docs/calc/water_share.md](docs/calc/water_share.md) |
| Покров | ESA WorldCover 10 м: `built`, `tree`, `open`, `water_wc` рядом с OSM-водой; калибровка — [docs/calc/landcover.md](docs/calc/landcover.md), таблица — [water_share_calibration.md](docs/calc/water_share_calibration.md) |
| Порядок и расход | HydroRIVERS v1.0: `site.hydro` — главный участок в 2 км (порядок по Стралеру, средний расход, расстояние), у реки — `order`/`discharge_m3s` при совпадении геометрии (правило — [docs/calc/hydro.md](docs/calc/hydro.md)) |
| Водные врата | где вода уходит из круга 8 км, ширина долины, высоты бортов, `enclosure` и `closure_index`; при упоре замера в предел — `width_capped` и `null` с причиной `flat_valley` (формула — [docs/calc/water_mouth.md](docs/calc/water_mouth.md)) |
| Видимость ухода воды | прямая видимость по рельефу из точки с глазом 2 м |
| Скрытая вода | culvert, covered, underground → `kind: culvert`; труба — свойство всей линии (`hidden_share ≥ 0.8`), а не ближайшего куска: иначе поверхностная река с коротким тоннелем становится трубой |
| Излучина | минимальный разрыв между двумя частями русла, разнесёнными по длине ≥1.5 км; петля не зависит от участка, положение участка — отдельным полем `site_position` |
| Направление течения | уклон рельефа регрессией по длине (±2 км) с `dem_slope_snr`; пять правил выбора, в пакете `flow_chosen`, `flow_rule`, `flow_confidence` (приливная река — решает OSM, при расхождении пишется предупреждение `flow_conflict`) |

Лондон, Сити (пакет `examples/london-city`, `water 7.4.0`, `pack 2.0.0`): 750 объектов воды в
`water.geojson` (471 контур, 25 рек, 74 ручья, 70 каналов, 63 дока, 47 труб), из них 47 в трубе
и потому невидимы (`kind: culvert`, `visible: false`); в пакет попадают 44
значимых. Темза — 463.6 м, вход 坤, выход 辰, участок снаружи изгиба (`bend: outer`) и на
вогнутой стороне петли Айл-оф-Догс (`bend_kind: loop`, `site_position: outside_concave`),
приливная (`tidal: true`, граница — Теддингтон, источник `osm_tag`), направление выбрано
правилом 2 (приливная река: решает OSM, уверенность `medium`). Fleet — 404.3 м,
`hidden_share 0.93`, `visible: false` (暗水), 7 кусков. Слияний в пакете — 47 (только между
руслами, контуры водоёмов в них не участвуют — E-017), в том числе Флит × Темза в 603.1 м;
вход русла в водоём пишется отдельно, в `waterbody_links` (9 записей: Regent's Canal входит
в четыре бассейна, `#5122307` — в Kingsland Basin и др.). Темза у Лондона склеена в 5 линий: главное русло плюс русла вокруг
островов — это разные водные пути, и в пакете они видны как `pieces`.
Роль рельефа: у Темзы в городе уклон по DSM не читается (`dem_reason: no_dem_values`), и это
записано, а не выдано за измерение.

**Чего пока нет и почему:**

- доля воды считается только по полигонам: река осевой линией в неё не входит (её длина —
  `sectors[].water_km`), а площадные отношения-мультиполигоны в выборку не попадают;
- порядок реки и расход есть только в пределах Европы (слой `eu` HydroRIVERS) и без имён —
  сопоставление с OSM по геометрии;
- в OSM приливность есть не везде: где нет ни тега, ни записи в таблице, `tidal: null`;
- `closure_index` — эвристика по уклону бортов, а не канонная мера; уверенность пишется рядом.

## Ориентация, склонение, ветер

- `orientation.facing_true_deg` — истинный азимут, `facing_mag_deg` — компасный
  (`истинный − склонение`), склонение по WMM считается офлайн (правило — [docs/calc/climate.md](docs/calc/climate.md)).
- `exposure.wind_prevailing_deg` — преобладающее направление ветра по ERA5 за 10 лет
  (векторный средний перенос), рядом скорость, доля штилей, сезонное сравнение и повторяемость
  по секторам (`sectors[].wind_share`).

  прилив без тега, высоты ниже нуля, классические фэншуй-места). Факты в `expect.yaml`
  с источниками, тесты офлайн на сохранённых ответах OSM и вырезанном DEM; состояние каждого —
  в [tests/golden/README.md](tests/golden/README.md).
- Сквозная проверка навыка: `tests/test_skill_e2e.py` собирает пакеты южных эталонов и Пекина
  офлайн и прогоняет `landform` навыка `vector-fengshui-bazi`, закреплённого коммитом:
  у южных — две интерпретации и раздел расхождений, у северного — одна.
- Версии алгоритмов в каждом пакете (`algo`), журнал изменений расчёта — [CHANGELOG-CALC.md](CHANGELOG-CALC.md),
  найденные ошибки — [docs/calc/errata.md](docs/calc/errata.md).
- `scripts/diff_packs.py old.json new.json` — что изменилось между двумя пакетами.
- CI: pytest без сети, `validate` на примерах, требование журнала при правке расчёта.

## Ловушки, уже учтённые

- **Copernicus DEM — модель поверхности (DSM)**: в городе крыши становятся «горами».
  Если Copernicus недоступен, рельеф берётся из SRTM 1″ (AWS Terrain Tiles) — источник
  пишется в `quality.dem_source`, а в предупреждениях сказано, что числа по рельефу
  несравнимы с пакетами на Copernicus ([docs/calc/dem.md](docs/calc/dem.md)).
  Поэтому макроформа считается по сглаженному слою (фильтр 300 м), а микрорельеф — отдельно;
  слои не смешиваются. Сглаживание обязательно, иначе «драконом» становится жилой квартал.
- **Nominatim** — публичный сервис с лимитом: соблюдается интервал 1.1 с, свой User-Agent,
  ответы кешируются на 30 дней (границы — на 90).
- **Азимуты только истинные**; склонение (WMM) будет отдельным полем на этапе 4.
